## Implementation Guide: Counting Duplicate Elements in C

### Overview
The C program ("q6.c") efficiently calculates the total number of duplicate elements in an array. It uses a **Frequency Array** approach, achieving linear time complexity at the expense of extra space proportional to the maximum value in the input array.

### Core Logic (`countDuplicates`)
The algorithm tracks occurrences using a dynamically sized frequency array:

1. **Find Maximum Value:** Scans the input array to find the maximum element (`max_val`) to determine the required size for the frequency array.
2. **Allocate Array:** Uses `calloc` to create a `freq` array of size `max_val + 1`, ensuring all initial frequency counts start at zero.
3. **Count Duplicates:** Iterates through the input array once. For each element:
   * If its count in `freq` is `> 0`, it has been seen before (increments `duplicate_count`).
   * Increments its count in `freq` to mark it as seen.
4. **Cleanup:** Frees the `freq` array before returning the count to prevent memory leaks.

### Testing Setup (`main`)
The `main` function sets up the test by:
* Dynamically allocating an array of size 100.
* Populating it with random integers between 0 and 1000 using `rand()`.
* Executing the duplicate counter and freeing the allocated memory.

### Complexity & Scalability
* **Time Complexity:** $O(N)$ - Requires only two linear passes (finding the max value, and counting duplicates).
* **Space/Memory Complexity:** $O(M)$ - Requires an auxiliary array of size $M + 1$, where $M$ is the maximum value in the input array.
* **Conclusion for Large $N$:** For a sufficiently large value of $N$, this method remains highly performant and scales perfectly linearly in execution time. It avoids the severe bottlenecks of $O(N^2)$ naive approaches and outperforms $O(N \log N)$ sorting methods, provided the maximum value ($M$) does not cause memory allocation issues.
