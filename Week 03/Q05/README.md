## O(n²) Divide and Conquer Matrix Multiplication

This repository contains a C implementation of a specialized Divide and Conquer matrix multiplication algorithm. While general matrix multiplication takes $O(n^3)$ time (or $O(n^{2.81})$ using Strassen's algorithm), this implementation achieves $O(n^2)$ time complexity by exploiting a very specific recursive block-symmetric matrix structure.

### How the Code Works

The code operates on square matrices of size $N 	imes N$, where $N$ must be a power of 2 (e.g., 2, 4, 8, 16) . 

1. **Matrix Initialization (`build_recursive`)**: 
   Instead of taking $N^2$ independent elements, the matrix is built from just $N$ independent elements (the first row) . It recursively partitions the matrix into four quadrants where:
   * Top-Left Quadrant ($M_1$) = Bottom-Right Quadrant ($M_1$) 
   * Top-Right Quadrant ($M_2$) = Bottom-Left Quadrant ($M_2$) 

2. **Divide & Conquer Multiplication (`multiply_dc`)**:
   Instead of multiplying rows by columns directly, the algorithm divides the matrices $A$ and $B$ into four smaller submatrices of size $N/2 	imes N/2$ . Because of the enforced symmetry, it only needs to perform **two** recursive multiplications instead of the standard eight .

3. **Memory Management**:
   The matrices are allocated dynamically. Temporary matrices (`sumA`, `sumB`, `diffA`, `diffB`, `P`, `Q`) are allocated at each recursive step to hold intermediate sums and products, and are freed before the function returns to prevent memory leaks .

### Maths behind this

Let $A$ and $B$ be matrices generated by the recursive pattern. At any level, they can be represented as block matrices:
$$A = \begin{pmatrix} A_1 & A_2 \\ A_2 & A_1 \end{pmatrix}, \quad B = \begin{pmatrix} B_1 & B_2 \\ B_2 & B_1 \end{pmatrix}$$

Standard block multiplication would yield:
$$C = A \times B = \begin{pmatrix} A_1 B_1 + A_2 B_2 & A_1 B_2 + A_2 B_1 \\ A_2 B_1 + A_1 B_2 & A_2 B_2 + A_1 B_1 \end{pmatrix} = \begin{pmatrix} C_1 & C_2 \\ C_2 & C_1 \end{pmatrix}$$

To minimize multiplications, the algorithm computes two intermediate matrices $P$ and $Q$:
* $P = (A_1 + A_2)(B_1 + B_2) = A_1 B_1 + A_1 B_2 + A_2 B_1 + A_2 B_2$ 
* $Q = (A_1 - A_2)(B_1 - B_2) = A_1 B_1 - A_1 B_2 - A_2 B_1 + A_2 B_2$ 

From $P$ and $Q$, we can extract $C_1$ and $C_2$ using simple element-wise addition and division by 2:
* $C_1 = \frac{P + Q}{2} = A_1 B_1 + A_2 B_2$ 
* $C_2 = \frac{P - Q}{2} = A_1 B_2 + A_2 B_1$ 

### Complexity overview

### Time Complexity: $O(n^2)$
Let $T(n)$ be the time to multiply two $n \times n$ matrices of this special form.
* The algorithm performs **2** recursive multiplications of size $n/2$ (to find $P$ and $Q$).
* It performs a constant number of matrix additions/subtractions of size $n/2$, which take $O(n^2)$ time.

The recurrence relation is:
$$T(n) = 2T(n/2) + O(n^2)$$

After solving the recurrence relation we find that the time complexity is bounded by $O(n^2)$.

### Space Complexity: $O(n^2 \log n)$
At each level of the recursion tree (which has depth $\log_2 n$), the algorithm allocates temporary $n/2 \times n/2$ matrices . The sum of spatial requirements across the recursion stack results in an upper bound space complexity of $O(n^2 \log n)$.

### Observation and output (plots if any)

* **Structural Preservation**: The resulting product matrix $C$ perfectly preserves the recursive $M = \begin{pmatrix} M_1 & M_2 \\ M_2 & M_1 \end{pmatrix}$ block structure of the inputs.
* **Plots**: The C code operates purely in the terminal and does not generate graphical plots. However, if one were to plot the empirical runtime of this algorithm against standard matrix multiplication ($O(n^3)$), this algorithm's curve would heavily flatten out (showing a quadratic parabola rather than a cubic curve) for large $N$, proving its efficiency.

#### How to Run

1. You can compile the C code and run the execution command:

```bash
gcc q5.c && ./a.out 
```

1. The program will prompt you to enter the number of elements.
2. Choose your initialization method:
   * **Option 1**: Auto-fills the independent matrix elements with random small integers (0-9).
   * **Option 2**: Allows you to manually type $N$ integers to populate the first row.
3. The program will display Matrix A, Matrix B, and the Resultant Matrix C.
